# Порядок работы

1. Выбрать конкретную ссылку из каталога Slurm и согласовать её для практики.
2. Прочитать страницу; записать изучаемые подразделы и версию документации.
3. Зафиксировать исходную конфигурацию стенда и версии программ.
4. Выполнять шаги по очереди. Если страница справочная, составить небольшой опыт
   для описанной настройки. Не включать в тему все связанные технологии.
5. В REPORT.md записывать команду, ожидаемое и фактическое поведение и объяснение.
6. Сохранять текстовый вывод в results/, скриншоты — в screenshots/.
   Использовать одинаковые номера: 01-environment, 02-submit, 03-result.
7. Скрипты заданий хранить в scripts/, изменённые конфигурации — в config/.
8. Записать способ возврата к исходному состоянию и выполнить его.
9. Проверить повторяемость и только после этого менять статус темы на «Пройдено».

## Что должно быть на скриншоте

Команда, значимая часть результата, JobID и состояние/причина, если они нужны
для вывода. Под изображением — объяснение наблюдения. Скриншот дополняет
текст команд и вывода: по одному изображению неудобно повторять эксперимент.

## Шаблон отчёта

Тема и ссылка → цель → окружение → шаги → результаты → вывод → восстановление.
Заготовка есть в каждом каталоге. Заполнять по мере работы, не выдумывать результаты.
Перед публичным коммитом проверить, что в кадре и логах нет паролей и ключей.

## Расширение проекта

Скопировать templates/lab в labs/NN-topic, указать название страницы и ссылку,
добавить строку в главный README. При необходимости добавить отдельный Compose
override или конфигурацию в каталог темы; базу менять только для общих улучшений.
Для каждой темы указывать ограничения среды: «Docker», «Linux VM», «GPU» и т. п.

## Завершение практики

Выбрать записи только по согласованным разделам, собрать итоговый документ
по требованиям учебного заведения и приложить ссылку на репозиторий.
Docker-стенд описать как окружение. Основная часть — прохождение документации
и полученные наблюдения. Формат и объём итогового отчёта уточнить у преподавателя.
