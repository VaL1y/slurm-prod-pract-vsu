# Базовый Docker-стенд

Один кластер: контроллер slurmctld, служба учёта slurmdbd, MariaDB и два CPU-узла.
Slurm 26.05.2. Сборка образа и запуск пока не проверены.

## Запуск

Все команды Compose выполнять из этого каталога:

    docker version
    docker compose config --quiet
    docker compose build slurmdbd
    docker compose up -d
    docker compose ps
    docker compose exec slurmctld scontrol ping
    docker compose exec slurmctld sinfo -N
    docker compose exec slurmctld sacctmgr list cluster

Если cluster linux отсутствует, проверить журналы и зарегистрировать его:

    docker compose exec slurmctld sacctmgr -i add cluster linux

Войти в Bash:

    docker compose exec slurmctld bash

Внутри:

    cd /data
    srun -N2 -n2 hostname
    sbatch --wrap="hostname"
    squeue
    sacct --format=JobID,JobName,State,ExitCode

Критерии: два зарегистрированных узла, вывод hostname от двух узлов,
успешное задание и запись о его завершении в sacct.
Это ожидаемые проверки, не уже полученные результаты.

## Файлы лабораторных

Каталог labs хоста подключён к контроллеру как /labs только для чтения.
Скопировать нужные задания из /labs/NN-topic/scripts в /data:
этот том общий с вычислительными узлами.
Результаты можно забрать на хост через docker compose cp.
Примеры upstream находятся в образе в /root/examples/jobs.

## Конфигурация

.env необязателен. Скопировать .env.example в .env для изменения параметров.
Имя проекта по умолчанию slurm-learning-lab; это отдельные тома и сеть.
При создании второго экземпляра использовать другое имя проекта.

config/ включается в образ и при первом запуске заполняет общий том etc_slurm.
Пересборка не обновляет уже существующий том: переносить изменения в рабочую
конфигурацию явно, сохраняя предыдущую версию, затем scontrol reconfigure.
Состояние контроллера, БД, рабочие файлы и конфигурация хранятся в именованных томах.

    docker compose down

Эта команда сохраняет тома. Не добавлять -v при обычной остановке.
Резервная копия БД — отдельная операция.

## Ограничения

Стенд использует общие CPU и память Docker-хоста. Автоматически обнаруженные
ресурсы каждого контейнера нельзя складывать как ресурсы независимых серверов.
До нагрузочных опытов согласовать лимиты Docker и параметры ресурсов Slurm.
Исходный профиль task/affinity + proctrack/linuxproc не доказывает жёсткую
изоляцию памяти через cgroups. Привилегированные контейнеры унаследованы от
учебного upstream; не использовать этот профиль как production-конфигурацию.

Вход по умолчанию — root. Перед опытами QOS создать обычных пользователей
с согласованными UID/GID на всех узлах и зарегистрировать ассоциации в Slurm.
Проверять пользовательские ограничения от их имени.

Сервисы GPU, REST, портал, Elasticsearch/Kibana из запуска удалены.
Оставшиеся неактивные ветви исходных файлов можно упрощать после первого
рабочего запуска либо использовать для следующих лабораторных.
Базовые образы имеют плавающие теги; после сборки записать digest.
